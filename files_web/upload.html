EXPERIENCED USERS ONLY: Configure the sizes of chunks uploaded to the server and the amount of parallel connections held to the server. Due to browser technology, we are not able to achieve a perfect parallel upload in the way that we would like to, however, setting more parallel connections means less time spent between chunks on handshakes with the server. Keep in mind that the connection to our server does not allow more than 100 MB to be sent at once, and based on our testing, it is better if connections times size stays comfortably under that number too. We recommend keeping the size under 50 MB under any conditions. The default, tested setting we recommend is 3 × 30, and if you're on a weak connection, you may want to lower the size so that you have more backup if the connection drops — try lowering to as low as 1, for example 3 × 1 on hotel wifis. Keep in mind that switching takes time though, so if it's not that bad, 5 or 10 would be a better choice.
Auto copy
All users: Our site automatically copies the link to your upload whenever it is done. While it may seem inconvenient, it sometimes does ask whether you allow it to access your clipboard on the first time — that is fine and you can accept it. We DO NOT access any contents in your clipboard unless you manually paste a file or text.
When a tool link is available
Some uploads also generate a dedicated "tool" page alongside the regular file link — currently that's the text/markdown reader or the audio player, with more kinds possibly added later. This decides which one auto copy grabs by default when both exist — the Off/Normal/Styled choice above still applies on top of whichever one is picked.
If an image was uploaded
Images already embed nicely as plain links almost everywhere (chat apps, forums, etc. generate their own preview), so you don't need the Styled markdown link nearly as often. This overrides the Normal/Styled choice above specifically for images — default is Normal.

IMPORTANT NOTICE: You are uploading files to the publicly accessible internet. Anyone with the link can access them. To protect your privacy, never upload sensitive data and set the expiration date as short as possible. Please note that the site administrator has direct access to all stored files for maintenance and moderation purposes. More information about how we handle your data can be found on our privacy page.

CONTENT POLICY: Please do not upload any content that is illegal, copyrighted (piracy), or violates our terms. Doing so puts the platform at risk. If any illegal content is found, it will be immediately deleted, and the user will likely be warned or restricted. Keep in mind that if law enforcement or legal authorities come knocking on our door, we will not hesitate to use and provide all stored metadata against the responsible person. A good rule of thumb: if you wouldn't want to be publicly confronted or held accountable for a file, it does not belong here.

DATA COLLECTION NOTICE: We only collect data that is essential to keep the service functional, stable, and secure. This includes session tokens (so you don't have to log in every time) and your upload history for cross-device syncing. For security reasons, we also automatically log certain metadata for every transaction (including initiated or unfinished uploads). This includes the precise time, expiration date, file details, and network routing information (including your IP address and geographic location data). This data is securely stored for 4 months. It is never shared with third parties, and the site administrator (more details on who that is can be found on the privacy page) does not intentionally inspect it unless a violation occurs. Note on Cloudflare: We use Cloudflare to ensure security and connectivity. They automatically process basic network metadata to protect the site from attacks. You can learn more about how they handle data in their privacy policy.
